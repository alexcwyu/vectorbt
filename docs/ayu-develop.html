Purpose and scope

Broadcast price/order/signal arrays, run portfolio simulations, retain pandas labels and calculate performance.

Design decisions

Decision Rationale Tradeoff Evidence
Keep array computations separate from pandas metadata. Broadcasting and wrappers support parameter and asset comparisons with labelled outputs. A shape or dtype unsupported by Rust can require another engine path. Portfolio.from_orders (L1624) / Portfolio.from_signals (L2055) / ArrayWrapper.from_obj (L358) / ArrayWrapper.wrap (L535) / simulate_from_orders (L537)

Strengths and limits

Strengths

  • The inspected fork has source-backed Rust/Numba dispatch, rather than a Numba-only architecture. simulate_from_orders (L537)

Limitations

  • Historical provider adapters fetch data. Their presence does not establish live order execution. YFData.download_symbol (L260) / CCXTData.download_symbol (L612)
  • Simulation assumptions and input layout determine backend support and execution realism. Portfolio.from_orders (L1624) / Portfolio.from_signals (L2055) / simulate_from_orders (L537)
